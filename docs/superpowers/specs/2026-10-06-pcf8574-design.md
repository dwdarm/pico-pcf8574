# PCF8574 Driver for RP2040 — Design Spec

```

```

Driver owns only the PCF8574 byte protocol. Caller owns `i2c_init`, GPIO function select, and baudrate (100 kHz default, 400 kHz supported).

## 2. API & Components

```c
typedef struct {
  i2c_inst_t *i2c;
  uint8_t addr;       // 0x20-0x27 or 0x38-0x3F
  uint8_t out_state;  // last written latch, init 0xFF
} pcf8574_t;
```

All return `bool`, `true` = ACK success:
- `init(dev, i2c, addr, initial)` — validates addr range, writes `initial`
- `write_byte(dev, val)` / `read_byte(dev, *val)`
- `write_pin(dev, pin 0-7, level)` — read-modify-write on `out_state`
- `read_pin(dev, pin, *level)` — single bus read then mask
- `toggle_pin(dev, pin)` — flips `out_state` bit, no extra read
- `set_inputs_mask(dev, mask)` — sets 1s for input pins (e.g. `0xF0` = upper 4 as inputs)
- `is_connected(dev)` — probe via 1-byte read for bus scan

Quasi-bidirectional rule: inputs must be written `1`. `write_pin(pin, true)` releases the line; device read returns actual level.

## 3. Data Flow & I2C Behavior

No registers — every transaction is 1 byte at the device address:
- Write: `i2c_write_blocking(i2c, addr, &out_state, 1, false)` with timeout. On success update cache; on `PICO_ERROR_GENERIC` return false, cache unchanged.
- Read: `i2c_read_blocking(i2c, addr, &val, 1, false)`. `read_pin` uses a fresh bus read, never stale cache.
- Mixed I/O safety: `write_pin` writes full `out_state`, not read-modify-read from bus, so concurrent input changes can't corrupt outputs. Input pins kept `1` in cache.
- INT: device pulls INT low on input edge, releases on read. Poll helper — caller does `gpio_get(int_pin)==0 → read_byte()`. Example shows polling plus optional `gpio_set_irq_enabled(..., GPIO_IRQ_EDGE_FALL, ...)` callback that sets a flag (I2C read stays in main loop, never in IRQ).

## 4. Error Handling

- All public functions return `bool`. `false` = invalid arg (`NULL` dev/i2c, `pin > 7`, addr outside `0x20-0x27` and `0x38-0x3F`) or I2C NACK/timeout.
- No asserts, no `panic`, no dynamic alloc — safe in retry loops.
- `init` fails fast on bad addr without touching the bus.
- `read_*` never writes `*val` on failure (caller keeps last-good value).
- Timeout: `#define PCF8574_I2C_TIMEOUT_US 10000` in header, overridable at compile time. Cache only updates on ACK.

## 5. Testing & Success Criteria

1. Host unit tests (`tests/test_pcf8574_host.c`): `gcc` on host, stubs `i2c_inst_t` + `i2c_read/write_blocking` with fake device byte + NACK injection. Covers init validation, write_byte caching, write_pin RMW preserving inputs, read_pin masking, toggle, input-mask helper, error paths (NACK → false, out-param untouched).
2. On-device examples: `output_blink` (LED/logic-analyzer check) + `input_buttons` (USB serial print on change, INT on GPxx with pull-up). Manual pass = expected transitions at 100 kHz and 400 kHz, both PCF8574 and A variants if available.

Success = `cmake` builds library + examples against pico-sdk, `gcc tests/` passes on host, README wiring + scan snippet verified.

## Out of Scope (YAGNI)
